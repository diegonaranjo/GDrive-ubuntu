Reference for anyone working on this codebase: architecture, conventions,
and operational notes. See also [CONTRIBUTING.md](CONTRIBUTING.md) for the
development workflow and contribution process.

## Project

**GDrive** — a Google Drive desktop client for Ubuntu. GTK4/libadwaita window +
GTK3 system-tray daemon + `rclone` synchronization, driven by a native Rust core.

- **App ID**: `com.gdrive.Client` (daemon) / `com.gdrive.ClientUI` (window)
- **Config**: `~/.config/gdrive/settings.json`
- **Sync target** (default): `~/GoogleDrive`

---

## Architecture

```
gdrive-app.py          # GTK4/libadwaita — main window (6 pages)
gdrive-tray.py         # GTK3/AppIndicator3 — system tray icon
launch.sh              # launches daemon + tray + window
install.sh             # system install (requires root)
build-deb.sh           # builds the .deb package
verify.sh              # verifies the installation
Makefile               # build / install / verify / uninstall targets
native/gdrive-core/    # native Rust core: config, sync (rclone bisync), logging, i18n, D-Bus daemon
native/gdrive-ui/      # Rust port of the GTK4 window (WIP: compiles, not installed, not in CI)
DEBIAN/control         # .deb metadata
nautilus-extension/    # Python Nautilus extension (context menu)
icons/                 # google-drive.svg + Lucide theme
desktop-files/         # .desktop launchers
```

### Architecture decisions

- **Separate processes**: `AyatanaAppIndicator3` is GTK3-only and cannot coexist
  with GTK4 in the same process.
- **Tray and engine via systemd**: `gdrive-tray.service` and
  `gdrive-daemon.service` (user services, generated by `setup.sh`).
- **Defaults**: `DEFAULTS` dict in `gdrive/config.py` (~30 options).
- **Logging**: `log_write()` with rotation, levels (error/info/debug/trace),
  export to zip. Stamps are **local time** on both sides (Python
  `time.strftime`, Rust `chrono::Local`); a UTC stamp here would sit hours away
  from the rclone output embedded in the same lines.
- **Native Rust core**: the `gdrive-daemon` binary performs synchronization and
  is exposed over D-Bus (`com.gdrive.Client`, path `/com/gdrive/Client`). The
  GTK4 UI and the tray talk to it via `gdrive/daemon_client.py`.

## Rules

### GTK3 vs GTK4

`gdrive-app.py` uses GTK4/libadwaita; `gdrive-tray.py` uses GTK3/AppIndicator3.
**Never mix GTK versions in the same process.**

GTK4 idioms:

- `append()`, `set_margin_end()`, `set_hexpand()`

GTK3 idioms:

- `pack_start()`, `pack_end()`, `set_margin_right()`, `set_margin_left()`

### Rust (`native/gdrive-core/`)

Apply the [Apollo GraphQL Rust Best
Practices](https://github.com/apollographql/rust-best-practices):

1. **Typed errors** with `thiserror` (`src/error.rs`); never `Result<T, String>`.
2. **No `unwrap`/`expect` in production code.** `Mutex::lock().unwrap()` is
   tolerated for poisoning recovery (documented rationale).
3. **Document every public item** (`#![deny(missing_docs)]`; the `daemon` module
   allows `missing_docs` because zbus's `#[interface]` macro generates
   undocumented public glue).
4. **Import order** `std` → external → crate (enforced manually; rustfmt's
   unstable import grouping is intentionally not used).
5. **Lints** in `Cargo.toml` `[lints]`; CI runs
   `cargo clippy --all-targets --all-features --locked -- -D warnings`.

### Adding an icon

1. Verify it exists:
   `python3 -c "import gi; gi.require_version('Gtk','4.0'); from gi.repository import Gtk,Gdk; t=Gtk.IconTheme.get_for_display(Gdk.Display.get_default()); print(t.has_icon('<name>-symbolic'))"`
2. If missing, download from
   `https://raw.githubusercontent.com/lucide-icons/lucide/main/icons/<NAME>.svg`
3. Copy to `~/.local/share/icons/hicolor/scalable/<CONTEXT>/`
4. Run `gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor`
5. **Do not use the `ui/` folder** — GTK4 does not search there for symbolic
   icons.

## Configuration (`~/.config/gdrive/settings.json`)

~30 options; see `DEFAULTS` in `gdrive/config.py`. Key options:

- `sync_dir`: destination folder (default `~/GoogleDrive`)
- `sync_interval`: `manual`, `5min`, `15min`, `30min`, `1hr`
- `sync_mode`: `mirror`, `stream`, `selective`
- `paused`: boolean
- `bandwidth_limit`: empty string = no limit
- `logging_enabled`, `log_level`, `log_rotate`, `log_max_size_mb`, `log_max_files`

## systemd services

```bash
# Sync engine (Rust daemon)
systemctl --user status gdrive-daemon.service
systemctl --user restart gdrive-daemon.service
systemctl --user enable gdrive-daemon.service

# Tray icon
systemctl --user status gdrive-tray.service
systemctl --user restart gdrive-tray.service
systemctl --user enable gdrive-tray.service
```

`setup.sh` generates both units under `~/.config/systemd/user/` with this
clone's absolute paths. `gdrive-daemon.service` supervises the engine
(`Restart=on-failure`, `PartOf=graphical-session.target`), so `rclone` children
stay in the unit's cgroup and a crash restarts without the UI noticing. When
the unit exists, `launch.sh` and `gdrive/helpers.py::start_daemon_service()`
start the engine through systemd instead of spawning a second copy; the spawned
copy would exit **0** anyway, because a duplicate losing the D-Bus name is the
intended singleton behavior, not a fault (that is what keeps
`Restart=on-failure` from looping).

### Verifying the services

```bash
systemctl --user is-enabled gdrive-daemon.service gdrive-tray.service
ls ~/.config/systemd/user/graphical-session.target.wants/ | grep gdrive
ls ~/.config/systemd/user/default.target.wants/ | grep gdrive   # must print nothing
systemctl --user show gdrive-daemon.service gdrive-tray.service -p Id -p PartOf
systemctl --user kill -s KILL gdrive-daemon.service; sleep 8
systemctl --user show gdrive-daemon.service -p ActiveState -p MainPID -p NRestarts
```

Both units belong to `graphical-session.target` (`WantedBy`) and are stopped
with it (`PartOf`). A tray unit wanted by `default.target` and missing `PartOf`
survives session teardown until the display connection dies under it; GTK then
exits 1, and `Restart=on-failure` relaunches a copy that dies again within a
few hundred milliseconds (`journalctl --user | grep gdrive-tray` shows the
`status=1/FAILURE` pair). After a real logout, the check is:

```bash
journalctl --user -b -1 -u gdrive-tray.service | tail -5
```

Expect `Stopping…` → `Deactivated`/`Succeeded`, not `Main process exited …
status=1/FAILURE` followed by a restart.

To measure `PartOf` without ending your own session (stopping
`graphical-session.target` takes the desktop down with it), use a scratch
target and two dummy units — one with `PartOf=`, one without — and stop the
target. Measured here: the `PartOf` unit ends `inactive/dead Result=success
NRestarts=0`, the one without it stays `active/running`. Delete the probe units
and `systemctl --user daemon-reload` afterwards.

## Publication guard

Pushed commits cannot be taken back: after a ref rewrite GitHub still serves
the old objects by SHA (commit API and tarball) until the repository itself is
deleted. This project therefore blocks identities and secrets locally, before
the push.

- `tools/secret-scan.sh` is the single implementation, run as `staged` by
  `tools/githooks/pre-commit`, as `range <A..B>` by `tools/githooks/pre-push`
  and by the CI `guard` job. `setup.sh` installs the hooks with
  `core.hooksPath` and adds `git-guard.*` to `.git/info/exclude`.
- Identity policy is asymmetric on purpose so contributors are not blocked:
  `.git/git-guard.deny` (untracked, seeded from the machine's global
  `user.email`) refuses that address; `git config gitguard.strict-identity true`
  (set by `setup.sh` when the clone already signs noreply) requires
  `@users.noreply.github.com` for every commit; anything else only prints a note.
  `.git/git-guard.local` allows additional addresses.
- Content rules are derived at run time (`$HOME`, `$USER`, `id -un`) and the
  patterns are generic, so the guard never writes a personal identifier into
  the repository. Test a change to it against known-bad commits before
  trusting it: detection without a non-zero exit is worthless (a pipeline put
  `scan_stream` in a subshell once and the script reported findings while
  passing).

## Known issues

- **Nautilus crash from dual-loading libpython3.14**: having a custom Python in
  `/usr/local/lib/` together with the system one in `/usr/lib/` causes
  `free(): invalid pointer`. Fix: move the custom libs.
- **GNOME Online Accounts has no Google Drive**: on Ubuntu 24.04+, GOA 3.58
  dropped file support. Use rclone.
- **`rclone authorize` does not auto-update the config**: the token must be
  copied manually into `~/.config/rclone/rclone.conf`.

## Useful commands

```bash
# Run the app
python3 gdrive-app.py

# Restart the tray
systemctl --user restart gdrive-tray.service

# Restart the sync engine
systemctl --user restart gdrive-daemon.service

# Watch logs
tail -f ~/.config/gdrive/debug.log

# Verify the installation
./verify.sh

# Build the .deb
make build

# Manual sync (newest file wins; plain --resync would let the remote win)
rclone bisync gdrive:/ ~/GoogleDrive --conflict-resolve newer --resilient
```
